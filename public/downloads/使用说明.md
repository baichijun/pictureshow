## 它是怎么工作的？

pictureshow 是部署在 **GitHub Pages** 上的静态网站，图片的真正「后端」就是 GitHub 仓库
（`baichijun/pictureshow`）。仓库里 `picture/<相册名>/` 下的图片，会在每次推送后由
GitHub Actions 自动生成缩略图、写入 `albums.json` 并发布上线。

所以本工具通过 **GitHub Contents API**（网站的后端接口）来上传图片：

1. 取脚本 / exe 所在文件夹的名字作为**相册名**；
2. 上传前先**自检 Token 是否具备写入权限**（避免逐张失败）；
3. 调用 API 查询网站上是否已有同名相册、以及已有哪些图片；
4. **相册不存在** → 创建并上传文件夹里的全部图片；
5. **相册已存在** → 只上传「本地有、网站上没有」的新图片（按文件名比对）；
6. 上传后 GitHub Actions 会自动构建并发布，几分钟后即可在网站看到新图片。

> 删除本地图片**不会**删除网站上的图片，符合项目 PRD 的要求。

## 准备：GitHub 访问令牌（只需一次）

上传需要对仓库的**写入**权限。若出现
`HTTP 403: Resource not accessible by personal access token`，
说明当前 Token **只有只读权限**，按下面任一方式重新生成。

### 方式一（最简单）：经典 Token（Classic）

1. 打开 <https://github.com/settings/tokens/new> （注意是 `tokens/new`）
2. 勾选 **`repo`**（整项即包含读写，无需逐项设置）
3. 点 **Generate token**，复制整串

### 方式二（更安全）：细粒度 Token（Fine-grained）

1. 打开 <https://github.com/settings/personal-access-tokens/new>
2. **Repository access** → `Only select repositories` → 勾选 **pictureshow**（必须先选仓库，下面的权限项才会出现）
3. 往下滚到 **Permissions → Repository permissions**，找到 **Contents**
4. 把 **Contents** 的下拉从 `Read-only` 改成 **`Read and write`**（这一步最关键）
5. 点 **Generate token**，复制整串

> Token 只显示一次，复制后妥善保存。首次运行工具时按提示粘贴，
> 之后会保存到 `~/.pictureshow-sync.json`（Windows 为 `C:\Users\你的用户名\.pictureshow-sync.json`），
> 以后在任意文件夹运行都无需再次输入。

### 更换 / 清除 Token

删除配置文件后重新运行并粘贴新 token 即可：

- Windows：`C:\Users\你的用户名\.pictureshow-sync.json`
- Mac / Linux：`~/.pictureshow-sync.json`

工具检测到写入权限不足（403）时，也会**当场提示是否输入新 Token**。

### 可选：用环境变量提供配置

`PICTURESHOW_TOKEN`、`PICTURESHOW_OWNER`、`PICTURESHOW_REPO`、`PICTURESHOW_BRANCH`。
默认仓库为 `baichijun/pictureshow`，分支 `main`（推送到该分支会触发自动部署）。

## 获取工具的三种方式

1. **从网站下载**：登录管理页（点右上角齿轮 → 输入密码）→「同步工具下载」区，
   下载 `pictureshow同步.py`（及可选的 `build-exe.bat`）。
2. **从仓库取**：本目录 `desktop-sync/` 下的 `pictureshow同步.py`。
3. **自行打包 exe**：见[用法 B](#用法-b打包成-windows-可执行文件exe)。

## 用法 A：直接用 Python 运行（Windows / Mac / Linux 通用）

1. 确保已安装 **Python 3**（Windows 在 <https://www.python.org/downloads/> 下载，安装时勾选 *Add to PATH*）。
2. 把 `pictureshow同步.py` 复制到某个**图片文件夹**里（该文件夹名就是相册名）。
3. 运行：
   - Windows：双击 `pictureshow同步.py`（或右键「用 Python 运行」）。
   - Mac / Linux：在该文件夹打开终端执行 `python3 pictureshow同步.py`。
4. 首次运行按提示粘贴 Token，随后自动上传。

## 用法 B：打包成 Windows 可执行文件（.exe）

适合不想装 Python 的电脑使用：在一台有 Python 的机器上打包一次，exe 可拷到别处直接双击。

1. 安装 Python 3。
2. 双击运行本目录下的 **`build-exe.bat`**（会自动安装 PyInstaller 并打包）。
   - 等价手动命令：
     ```bat
     pip install pyinstaller
     pyinstaller --onefile --console --name pictureshow-sync --clean --noconfirm pictureshow同步.py
     ```
     （脚本会自动把产物重命名为 `pictureshow同步.exe`）
3. 生成的 `dist\pictureshow同步.exe` 就是最终程序（约 8MB）。
4. 把这个 `.exe` **复制到任意一个图片文件夹**中，**双击**即可把该文件夹同步到网站。

> 若提示找不到 `pip`，改用 `py -m pip install --upgrade pyinstaller` 再打包。

## 用法 C：Mac 做成可双击的 .app

最简单的做法是用 **Automator**：

1. 打开「自动操作」→ 新建「应用程序」。
2. 添加「运行 Shell 脚本」动作，内容：
   ```bash
   cd "$(dirname "$0")"
   /usr/bin/python3 "pictureshow同步.py"
   ```
3. 存为 `pictureshow同步.app`，与图片放在同一文件夹即可双击运行。

或使用 [py2app](https://py2app.readthedocs.io/) 打包；逻辑与脚本完全一致。

## 常见问题（FAQ）

**Q：报 `HTTP 403: Resource not accessible by personal access token`？**
A：Token 没有写权限。按[准备令牌](#准备github-访问令牌只需一次)重新生成（经典勾 `repo`，
或细粒度把 Contents 设为 Read and write），删除 `~/.pictureshow-sync.json` 后重试。

**Q：上传成功了，但网站没变化？**
A：上传只是写入仓库，需等 GitHub Actions 构建+发布（约 1～2 分钟），再刷新网站。

**Q：会重复上传吗？**
A：不会。已存在同名文件会被跳过，只上传新增文件。

**Q：删了本地图片，网站会删吗？**
A：不会。本工具只新增、不删除网站图片。

**Q：子文件夹里的图片会上传吗？**
A：不会。只同步文件夹**第一层**的图片。

## 注意事项

- 仅同步文件夹**第一层**的图片文件，不递归子目录（与网站相册结构一致）。
- 支持的格式：`jpg jpeg png gif webp bmp tiff tif avif`。
- 比对依据是**文件名**：网站上已存在同名文件就跳过，只上传新增文件。
- 默认目标分支为 `main`（触发部署）；如改用其它分支，记得该分支也要能触发构建。
- 上传后请稍等几分钟（GitHub Actions 构建+发布）再刷新网站查看。
